# Мои финансы — простой учёт доходов и расходов

Небольшое учебное Android-приложение на Kotlin с обычной XML-разметкой. Один экран: общие доходы, расходы, остаток, форма добавления и таблица операций. Без входа, сервера, банковских подключений и базы данных.

[Скачать APK и исходники](https://github.com/KimberlyWay/finance-tracker/releases/latest) · [GitHub Actions](https://github.com/KimberlyWay/finance-tracker/actions) · [Исходники main в ZIP](https://github.com/KimberlyWay/finance-tracker/archive/refs/heads/main.zip)

## 1. Что умеет приложение

- Показывает таблицу: дата, описание, доход, расход.
- Добавляет доходы и расходы с выбранной датой.
- Считает сумму доходов, сумму расходов и остаток за **весь список записей**.
- Удаляет запись по нажатию на строку с подтверждением.
- Сохраняет данные на этом телефоне между запусками.

Все суммы в рублях, с точностью до копейки. У дохода заполнена колонка «Доход», у расхода — «Расход», в другой колонке стоит прочерк. Таблица сортируется от поздней даты к ранней; среди операций одной даты новые добавленные записи показываются первыми.

В таблице четыре колонки, поэтому на узком экране она прокручивается **влево и вправо**. Весь экран также можно прокручивать вверх и вниз.

## 2. Как пользоваться

1. Открыть «Мои финансы».
2. Выбрать тип: «Доход» или «Расход».
3. Ввести сумму, например `1500`, `1500,50` или `1500.50`.
4. Ввести описание, например «Подработка» или «Продукты». Если поле пустое, будет использовано название типа операции.
5. Если нужна другая дата, нажать кнопку с датой и выбрать её в календаре.
6. Нажать «Добавить». Запись появится в таблице, итоги пересчитаются.
7. Для удаления нажать строку таблицы и подтвердить «Удалить». «Отмена» сохраняет запись.

Разрешены суммы от **0,01 до 999 999 999,99 ₽**, не более двух знаков после разделителя. Ноль, отрицательные значения и три знака после запятой не принимаются. Знак минус вводить не нужно: расход задаётся переключателем. Разделители тысяч, пробелы внутри числа и знак рубля в поле суммы не вводятся.

Описание ограничено 100 символами. После добавления поля суммы и описания очищаются, выбранная дата и тип остаются — удобно вводить несколько операций подряд.

Остаток — это только **доходы минус расходы из таблицы**, начальный банковский баланс не подгружается. Остаток может быть отрицательным; тогда он показывается красным. Доходы отмечены зелёным, расходы — красным.

## 3. Начальные данные и сохранение

При самом первом запуске создаются три примера с текущей датой:

| Описание | Доход | Расход |
|---|---:|---:|
| Зарплата | 45 000,00 ₽ | — |
| Подработка | 3 000,00 ₽ | — |
| Продукты | — | 1 800,00 ₽ |

Итоги этих примеров: доходы **48 000,00 ₽**, расходы **1 800,00 ₽**, остаток **46 200,00 ₽**. Это демонстрационные значения, их можно удалить и заменить своими.

Записи хранятся в стандартном `SharedPreferences` Android как строка JSON. Базы данных SQLite/Room нет. После закрытия приложения записи остаются. Если удалить все строки, после повторного запуска примеры **не появятся заново**: сохраняется пустой список.

После удаления приложения или очистки его данных записи исчезнут. Между разными телефонами синхронизации нет. Приложение работает в авиарежиме и не запрашивает сетевых разрешений.

SharedPreferences подходят для небольшого учебного списка: после изменения записывается весь массив операций. Для большой истории и настоящего финансового сервиса потребовалось бы другое хранилище. Экспорт, графики, фильтрация по месяцам и редактирование готовой строки в этот простой проект не включены. Чтобы исправить строку, её можно удалить и добавить заново.

## 5. Открытие в Android Studio

### Скачать и распаковать

1. Открыть репозиторий и выбрать `Code → Download ZIP` либо скачать исходники из релиза.
2. Распаковать архив, например в `C:\Projects\FinanceTracker`.
3. Найти корневую папку, внутри которой лежит `settings.gradle.kts`.

Не открывать проект внутри ZIP. В архиве GitHub уже нет папки `.git`, поэтому для этого способа Git не нужен.

Для клонирования через `Clone Repository` / `Get from VCS` в Android Studio:

```text
https://github.com/KimberlyWay/finance-tracker.git
```

### Открыть и настроить

1. В Android Studio нажать `Open` либо `File → Open`.
2. Выбрать **папку с `settings.gradle.kts`**, а не только вложенную `app`.
3. Подтвердить доверие к проверенным исходникам, если Studio спросит.
4. Дождаться Gradle Sync и скачивания зависимостей.
5. В `Tools → SDK Manager` установить Android SDK Platform 35 и Build Tools 34.0.0, если их нет.
6. В `Settings → Build, Execution, Deployment → Build Tools → Gradle` выбрать Gradle JDK 17. При необходимости воспользоваться `Download JDK`.

Названия меню могут отличаться между версиями Studio. Не обязательно сразу обновлять AGP и Gradle — сначала стоит собрать проект с указанными версиями.

`local.properties` с путём к SDK обычно создаётся Studio автоматически. Этот файл относится к конкретному компьютеру, его не нужно переносить с чужого устройства и коммитить.

### Если Gradle не скачивается

1. Посмотреть точный текст ошибки в `Sync` / `Build Output`.
2. Проверить интернет, доступ к адресу дистрибутива Gradle и выключенный Offline Mode.
3. Если используется прокси, проверить `HTTP Proxy` в Studio и настройки Gradle.
4. Повторить `Sync Project with Gradle Files`.

Адрес и версия Gradle указаны в `gradle/wrapper/gradle-wrapper.properties`. Ошибка скачивания сама по себе не доказывает ошибку кода: нужны конкретные адрес и сообщение, например timeout, SSL или неизвестный хост. Версии наугад менять не нужно.

На телефоне включить параметры разработчика и «Отладку по USB», подключить кабелем с передачей данных и подтвердить разрешение отладки для своего компьютера. В Studio выбрать телефон, конфигурацию `app` и нажать `Run`.

Если телефон не виден, проверить кабель, USB-режим, разрешение отладки и драйвер на Windows.

## 7. Как собрать APK

Через меню Android Studio найти действие сборки APK: обычно `Build Bundle(s) / APK(s) → Build APK(s)` либо `Generate App Bundles or APKs → Generate APKs`. Выбрать вариант `debug`.

Команды из корня проекта работают независимо от названий меню.

Windows PowerShell:

```powershell
.\gradlew.bat testDebugUnitTest lintDebug assembleDebug
```

Linux / macOS:

```bash
chmod +x gradlew
./gradlew testDebugUnitTest lintDebug assembleDebug
```

Готовый APK:

```text
app/build/outputs/apk/debug/app-debug.apk
```

`testDebugUnitTest` запускает тесты денежных значений, `lintDebug` — Android Lint, `assembleDebug` — компиляцию и упаковку APK. Они не заменяют проверку интерфейса на телефоне.

Передать APK на телефон и открыть через файловый менеджер. При необходимости разрешить установку из этого источника.

### Подпись и обновления

Используется отладочная debug-подпись. У локальной сборки и сборок на разных runner GitHub Actions ключи могут различаться. Если Android не позволяет установить новую версию поверх старой из-за несовпадения подписей, может потребоваться удалить предыдущую копию. **При удалении её записи пропадут.**

Для регулярных обновлений с сохранением данных нужен постоянный ключ подписи; в этом простом проекте он не настраивался.

## 8. GitHub Actions и релизы

Настройка находится в `.github/workflows/android.yml`.

Workflow запускается при изменениях в `main`, pull request, вручную через `Actions → Build APK → Run workflow` и по тегам `v*`, например `v1.0.0`.

Задача `build` устанавливает Java 17 и Android SDK, запускает тесты, Lint и сборку. APK сохраняется в artifact `finance-tracker-apk` на 30 дней.

Для скачивания artifact открыть успешный запуск Actions, внизу выбрать `finance-tracker-apk`, скачать ZIP и распаковать `app-debug.apk`. Для скачивания artifacts в интерфейсе GitHub обычно требуется вход.

Для тега `v*` после успешной сборки задача `release` создаёт GitHub Release с двумя вложениями:

- `finance-tracker-v1.0.0.apk` — для установки;
- `finance-tracker-source-v1.0.0.zip` — исходники того же коммита, включая README и Gradle Wrapper.

Описание релиза берётся из `RELEASE_NOTES.md`. Используется временный `GITHUB_TOKEN` самого workflow: у сборки права `contents: read`, у задачи публикации — `contents: write`. Личный токен в исходники или Secrets добавлять не нужно.

Пример следующего релиза после отправки коммита с изменённой версией приложения:

```bash
git tag v1.0.1
git push origin v1.0.1
```

Это пример для нового выпуска. Уже существующий релиз повторно создавать тем же тегом не нужно. Номер `versionCode` в Android и имя Git-тега меняются отдельно.

## 10. Как работает программа

### Запуск и разметка

Android находит `MainActivity` по `MAIN` и `LAUNCHER` в манифесте и вызывает `onCreate()`. `setContentView(R.layout.activity_main)` подключает XML. `findViewById(...)` находит элементы по их ID. Класс `R` создаётся системой сборки из ресурсов и не пишется вручную.

`ScrollView` прокручивает весь экран по вертикали. Внизу `HorizontalScrollView` содержит `TableLayout`, чтобы четыре колонки помещались независимо от ширины телефона. `LinearLayout` располагает элементы последовательно, `RadioGroup` обеспечивает выбор одного типа операции.

`dp` используются для размеров и отступов, `sp` — для текста. Метод `dp()` в Kotlin переводит размеры в пиксели экрана. Поля ввода с ID автоматически участвуют в восстановлении текста после поворота. Выбранная дата дополнительно сохраняется в `Bundle` через `onSaveInstanceState()`.

### Одна операция

```kotlin
data class Entry(val id: String, val date: String, val note: String, val income: Boolean, val amount: Long)
```

- `id` — уникальная строка для удаления именно этой операции;
- `date` — календарная дата в формате `YYYY-MM-DD`;
- `note` — описание;
- `income` — `true` для дохода, `false` для расхода;
- `amount` — положительное целое число копеек.

Для новых записей ID создаётся через `UUID.randomUUID()`. Даже две одинаковые суммы с одинаковой датой остаются разными операциями. Дата хранится как календарная строка, поэтому смена часового пояса не сдвигает её на другой день.

### Почему деньги в копейках

Для денежных значений здесь не используется `Double`. Например, `10,50 ₽` сохраняется как `1050L`. Целочисленное сложение не вносит двоичных ошибок округления.

`Money.parse()` сначала проверяет формат: от одной до девяти цифр до разделителя и, если разделитель есть, одну или две цифры после него. Запятая заменяется на точку. `BigDecimal` точно переводит значение в копейки, ноль отклоняется. Поэтому `0,10 + 0,20` даёт ровно 30 копеек.

`Money.number()` форматирует копейки обратно с двумя знаками после запятой и русскими разделителями. `Money.format()` дополнительно добавляет знак рубля. В таблице знак уже указан в заголовках колонок, поэтому ячейки показывают только число.

### Добавление и итоги

`addEntry()` проверяет сумму. При ошибке показывает подсказку у поля и ничего не сохраняет. При успехе определяет тип, получает описание и дату, создаёт `Entry`, добавляет её в начало списка, сохраняет и перерисовывает таблицу.

```kotlin
val income = entries.filter { it.income }.sumOf { it.amount }
val expense = entries.filter { !it.income }.sumOf { it.amount }
```

`filter` отбирает нужные операции, `sumOf` складывает их суммы. Остаток равен `income - expense`. Считаются все сохранённые операции, без фильтра месяца и без подключения к банковскому счёту.

### Дата и порядок строк

Кнопка даты открывает стандартный `DatePickerDialog`. В хранилище дата записывается как `2026-10-28`, на экране показывается как `28.10.2026`. Для строк вида `YYYY-MM-DD` обычная сортировка даёт правильный календарный порядок. Сортировка стабильна: среди одинаковых дат сохраняется порядок исходного списка, где новая запись стоит в начале.

Если календарь открыт во время поворота, он может закрыться; ранее выбранная дата в форме сохраняется.

### Таблица и удаление

`showEntries()` удаляет старые строки таблицы, добавляет заголовок и затем по `TableRow` для каждой операции. Фиксированные ширины колонок обеспечивают одинаковое выравнивание. У чётных и нечётных строк разные фоны.

Нажатие строки открывает `AlertDialog` с датой, описанием, типом и суммой. Только кнопка «Удалить» фильтрует список по ID, сохраняет результат и обновляет итоги. Подтверждение не изменяет другие записи с похожими значениями.

### Сохранение

`FinanceStorage` открывает `SharedPreferences` с именем `finances`. Ключ `entries` содержит JSON-массив. Каждый объект хранит поля класса Entry. `apply()` обновляет значения в памяти и записывает их на диск асинхронно.

Если ключ отсутствует, создаются и сразу сохраняются три примера. Если ключ есть, но массив пустой, загружается именно пустой список. Это различие не даёт примерам появляться снова после удаления всех записей.

## 11. Как изменить проект

### Примеры данных

В `FinanceStorage.load()` изменить список `examples`. Суммы задаются **в копейках**: 500 рублей = `50000`, 15 рублей 50 копеек = `1550`. Для дохода указать `true`, для расхода — `false`.

Новые начальные примеры не заменяют данные, уже сохранённые на телефоне. Чтобы вернуться к первоначальному состоянию, можно очистить данные приложения в настройках Android; при этом все свои записи удалятся.

### Название и оформление

`app_name` в `strings.xml` — название приложения, `screen_title` — заголовок экрана. Там же находятся подписи и ошибки. Цвета и стили общего экрана заданы в `styles.xml`; цвета таблицы и ширины колонок — в `MainActivity.kt`.

Если меняете форматированные строки `%1$s`, `%1$d` и подобные, нужно сохранять соответствие аргументам `getString(...)` в Kotlin.

### Номер версии

В `app/build.gradle.kts` для обновления увеличить `versionCode`, например до `2`, а `versionName` изменить на `"1.1"`. Затем пересобрать и установить APK. Изменение исходников не обновляет приложение на телефоне само по себе.

## 12. Что можно удалить после открытия в Android Studio

**Git и Gradle — разные инструменты.** Git хранит историю проекта, Gradle собирает APK. Открытие в Studio не делает файлы Gradle ненужными.

Перед очисткой сохранить копию проекта, закрыть Studio и остановить выполняющиеся сборки. Скрытые файлы можно показать через файловый менеджер.

### Необязательные для локальной сборки файлы GitHub

| Что можно удалить из локальной копии | Последствие |
|---|---|
| `.git/`, если проект клонирован | Удалятся локальная история, ветки и связь с удалённым репозиторием; код и репозиторий на GitHub останутся. |
| `.github/` | Локальная сборка продолжит работать. Если отправить удаление в GitHub, перестанут работать Actions и автоматические релизы. |
| `.gitignore` | На APK не влияет, нужен при работе с Git. |
| `README.md` | Исчезнет только инструкция. |
| `RELEASE_NOTES.md` | Локальной сборке не нужен, но автоматический релиз использует его. |

В ZIP из GitHub папки `.git` уже нет. `.github` и `.git` — разные каталоги. Для дальнейшей сборки и релизов через GitHub оставить `.github` и `RELEASE_NOTES.md` в самом репозитории.

Если после удаления `.git` Studio сообщает о старой привязке VCS, убрать запись папки в `Settings → Version Control → Directory Mappings`.

### Можно очистить: создастся заново

| Что | Что произойдёт |
|---|---|
| `.gradle/`, `.kotlin/` внутри проекта | Удалятся локальные данные инструментов, следующая сборка может идти дольше. |
| `build/`, `app/build/` | Удалятся APK, отчёты и результаты сборки. Нужный APK сначала скопировать. |
| `.idea/`, `*.iml` | Studio пересоздаст настройки; часть локальных предпочтений потеряется. |
| `local.properties` | Studio должна заново определить SDK; для терминальной сборки путь может потребоваться указать вручную. |

Для очистки результатов сборки достаточно `./gradlew clean` либо `.\gradlew.bat clean`. При обычном открытии проекта это не требуется.

### Оставить для сборки

- `app/src/` целиком;
- `app/build.gradle.kts`;
- корневые `build.gradle.kts`, `settings.gradle.kts`, `gradle.properties`;
- `gradle/wrapper/`, включая **`gradle-wrapper.jar`**;
- `gradlew` и `gradlew.bat`.

Файлы `gradlew` и каталог `gradle` относятся к Gradle, а не к Git. Удалять их ради «убрать GitHub» не нужно.

`app/src/test/` не содержит рабочего экрана и при удалении не меняет его поведение, но удаляет проверки денежных сумм. Удалять тесты для открытия проекта не требуется. Для сдачи исходниками удобно исключить `.git`, `.gradle`, `.kotlin`, `.idea`, `build`, `app/build`, `local.properties`, сохранив исходники, Gradle Wrapper и README.

## 13. Проверки и тесты

В `MoneyTest.kt` четыре теста:

1. Целые суммы, точка, запятая и одна копейка принимаются.
2. Пустые, нулевые, отрицательные и некорректные значения отклоняются.
3. Верхняя граница суммы проверяется.
4. `0,10 + 0,20` складываются точно, отображается и отрицательный остаток.

Для ручной проверки на телефоне:

1. Первый запуск показывает три примера и итоги 48 000 / 1 800 / 46 200 рублей.
2. Доход 100,50 увеличивает доход и остаток на 100,50, расход не меняется.
3. Расход 20,25 увеличивает расход и уменьшает остаток на 20,25.
4. Пустая сумма и ноль не добавляют строку, отображается ошибка.
5. Изменённая в календаре дата появляется в таблице, строки сортируются по дате.
6. Пустое описание заменяется словом «Доход» или «Расход».
7. Таблица прокручивается вбок, видны обе денежные колонки.
8. Нажатие строки и «Отмена» ничего не удаляют; «Удалить» удаляет только эту строку и пересчитывает итоги.
9. Записи остаются после закрытия и повторного открытия.
10. После удаления всех записей итоги нулевые, примеры не возвращаются после перезапуска.
11. При повороте сохраняются ввод в полях, тип и выбранная дата.
12. В авиарежиме все действия работают так же.

Тесты JUnit не запускают интерфейс Android. Запуск на телефоне проверяется отдельно от автоматической сборки.

## 14. Частые ошибки

| Проблема | Что проверить |
|---|---|
| Studio не видит проект | Открыта ли папка с `settings.gradle.kts`. |
| `SDK location not found` | SDK установлен и путь определён в Studio / `local.properties`. |
| Нет SDK 35 | Установить Android SDK Platform 35 в SDK Manager. |
| Ошибка Java при Sync | Выбрать Gradle JDK 17. |
| Gradle не скачивается | Проверить точную ошибку Sync, сеть, прокси, Offline Mode. |
| `Permission denied` для `gradlew` | На Linux/macOS выполнить `chmod +x gradlew`; на Windows использовать `.\gradlew.bat`. |
| Ошибка `R` | Исправить первую ошибку ресурсов в Build Output. |
| Не получается ввести расход с минусом | Вводится положительная сумма, тип выбирается переключателем «Расход». |
| Не виден столбец расходов | Прокрутить таблицу горизонтально. |
| Примеры из кода не изменились | На телефоне уже сохранены данные; новые начальные примеры их не перезаписывают. |
| Новая APK не ставится поверх старой | Проверить подпись; перед переустановкой учесть потерю записей. |
| Нет artifact | Проверить результат Actions и срок хранения, при необходимости запустить снова. |

## 15. Краткое объяснение для защиты

Приложение предназначено для простого учёта доходов и расходов. Оно написано на Kotlin, основной экран описан в XML. Пользователь задаёт тип операции, положительную сумму, описание и дату. Данные отображаются в TableLayout; доходы и расходы находятся в разных колонках. Итоги вычисляются по списку записей, остаток равен разнице доходов и расходов. Денежные суммы хранятся целым числом копеек, поэтому при сложении нет ошибок Double. Данные сохраняются локально как JSON в SharedPreferences, без базы данных и сервера. Сборка и проверки выполняются Gradle, а GitHub Actions собирает APK и по тегу выпускает релиз.
